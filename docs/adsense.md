# 애드센스 — 승인부터 운영까지

> **원본은 도구 저장소의 `guides/adsense.md`다.** 고칠 때는 그쪽을 고치고 여기에 복사한다.
> 두 벌을 따로 고치면 어긋난다.

승인 신청은 **글 15~25편이 쌓인 뒤**다. 지금 하면 거절 기록만 남는다.
이 문서는 그때가 됐을 때 순서대로 따라갈 것과, 승인 뒤 지킬 것을 담는다.

---

## 심사관이 묻는 것은 하나다

> **"여기에 내 광고주의 광고를 붙여도 광고주가 화내지 않을까?"**

애드센스 심사는 글솜씨 대회가 아니라 **신뢰도 검사**다.
거절은 무작위가 아니라 패턴이 있고, 그 패턴은 넷뿐이다.

| # | 거절 사유 | 심사관이 읽는 신호 |
|---|---|---|
| 1 | **콘텐츠 부족** — 개수가 적거나, 많아도 한 편이 얇다 | "진지하게 운영하지 않는다" |
| 2 | **복제·저품질** — 베끼기, 기사 옮기기, 짜깁기 | "정직하지 않다" |
| 3 | **정책 위반** — 단정적 투자 권유, 출처 없는 정보 | "광고 옆에 두면 위험하다" |
| 4 | **탐색 곤란** — 메뉴 없음, 빈 페이지, 신뢰 페이지 부재 | "아직 준비가 안 됐다" |

> 거절을 '운이 없어서'로 보면 고칠 행동이 사라진다. 할 일이 '재신청 버튼 누르기'만 남는다.
> '내가 빠뜨린 항목의 신호'로 보면 할 일이 또렷해진다. 전자는 도박, 후자는 작업이다.

## 1. 지금 상태 — 무엇이 갖춰졌나

### ✅ 이미 된 것

| 항목 | 어디에 |
|---|---|
| 신뢰 페이지 3장 | `/about/` `/privacy/` `/contact/` — 메뉴에서 한 번에 보인다 |
| 쿠키 고지 문구 | `content/privacy.md` — 애드센스가 명시적으로 요구하는 문장 |
| 실제 받을 수 있는 이메일 | `contact@onioniworks.com` (Zoho) |
| 면책 문구 자동 삽입 | `layouts/_partials/extend_post_content.html` — 개별 글로 끌 수 없다 |
| 게시자 ID를 설정값으로 | `hugo.toml`의 `adsenseClient`. 하드코딩 없음 |
| 광고 코드 한곳에 | `extend_head.html` 하나. 다른 파일에 적지 않는다 |
| 검수 게이트 | `draft: true`가 기본. 사람이 손으로 `false`로 바꿔야 발행된다 |
| 빈 카테고리 차단 | 글 0편 카테고리는 목록·검색에서 빠진다 (§4 참조) |
| 깨진 링크 | 없음 (전수 확인) |

### ⏸ 신청 전에 채워야 할 것

| # | 항목 | 왜 |
|---|---|---|
| 1 | **글 15~25편** | 거절 사유 1번. 지금 1편이다 |
| 2 | **소개 페이지의 운영자 문단** | "누가, 왜 운영하는가"를 증명하는 자리인데 비어 있다 |
| 3 | 파비콘 | 자잘한 미완성의 하나 |
| 4 | 사이트 제목·설명 확정 | `hugo.toml`에 임시값이 남아 있다 |

> "세 줄짜리 일기 100개보다, 검색자의 질문에 또박또박 답하는 본문 충실한 글 스무 편이 훨씬 강하다."

## 2. 신청 30일 전부터 — 순서대로

| 기간 | 할 일 |
|---|---|
| 1~7일 | 콘텐츠 점검 — 얇은 글 보강, 복제 의심 글 재작성 |
| 8~12일 | 신뢰 페이지 마무리 (운영자 문단·파비콘) + 메뉴 동작 확인 |
| 13~15일 | 단정 표현 제거 — "무조건", "보장", "확실히" 전수 검색 |
| 16~22일 | 탐색 점검 — 깨진 링크, 2~3클릭 내 도달, **휴대폰으로 직접** 메뉴 확인 |
| 23~28일 | 자가 점검 (아래 체크리스트). ✗ 하나라도 있으면 신청을 미룬다 |
| 29~30일 | 신청. **심사 중에도 글은 계속 발행한다** |

> 승인은 한 방의 운이 아니라 한 달의 축적이다.
> 이 작업은 승인만을 위한 게 아니라 오래가는 블로그의 기초 공사다. 떨어져도 남는다.

### 자가 점검 — ✗가 하나라도 있으면 미룬다

- [ ] 글이 15편 이상이고, 각 글이 검색자의 질문에 실제로 답하는가
- [ ] 남의 글을 옮기거나 짜깁기한 글이 없는가
- [ ] 단정적 권유·보장 표현이 없는가 (`niches/personal-finance/niche.md` 기준)
- [ ] 소개·개인정보처리방침·연락처가 메뉴에서 한 번에 보이는가
- [ ] **소개 페이지에 누가 운영하는지 적혀 있는가**
- [ ] 빈 카테고리·"준비 중" 페이지가 없는가
- [ ] 깨진 이미지·링크가 없는가 (전수 클릭)
- [ ] 연락처 이메일로 실제로 메일이 오는가 (직접 보내 본다)
- [ ] **휴대폰으로 열어** 메뉴가 동작하는가
- [ ] 파비콘이 있는가

> 거절은 큰 결함보다 **자잘한 미완성의 누적**에서 더 자주 온다.

## 3. 승인 뒤 — ads.txt

승인되면 게시자 ID(`ca-pub-…`)를 받는다. 두 곳에 넣는다.

**① `hugo.toml`**

```toml
adsenseClient = 'ca-pub-XXXXXXXXXXXXXXXX'
```

**② `static/ads.txt`** — 이때 만든다. 미리 만들면 틀린 ID가 박힌다.

```
google.com, pub-XXXXXXXXXXXXXXXX, DIRECT, f08c47fec0942fa0
```

- `pub-` 뒤 번호는 **본인 것**이어야 한다. 마지막 칸은 구글 인증 ID로 누구나 같다
- `ca-pub-`이 아니라 **`pub-`** 으로 시작한다. `hugo.toml`과 접두사가 다르니 주의
- 없으면 "승인된 광고 판매자 없음" 경고가 뜨고 수익이 제한된다
- 구글 재크롤링에 며칠 걸린다. `https://blog.onioniworks.com/ads.txt`가 열리는지만 확인하고 기다린다

## 4. 광고 배치 — 승인 뒤에 정한다

### 순서를 거꾸로 알지 않는다

> 광고 배치는 **이미 들어온 트래픽에서 수익을 짜내는 기술**일 뿐, 트래픽 자체를 만들지 못한다.
> 배치에 며칠 매달려 픽셀을 옮기는 것보다, 그 시간에 글 한 편 더 쓰는 게 대개 더 큰 수익이다.

**광고는 콘텐츠의 손님이지 주인이 아니다.** 한 번 제대로 세팅하고 가끔 점검한다.

### 광고를 늘리면 단가가 내려간다

광고는 자리를 파는 장사인데, **좋은 자리는 희소할 때 비싸다.**
자리를 마구 늘리면 그 자리들의 가치가 다 같이 떨어진다.
두 배로 늘려도 단가가 절반이면 수익은 제자리다.

### 어디에 두나 — 시선이 쉬는 곳

- 본문 첫 문단 근처 (제목을 읽고 본문으로 넘어가는 찰나)
- 문단과 문단 사이 (호흡)
- 본문 끝 ("이제 뭘 하지?" 하며 시선이 떠도는 곳)

외울 필요 없다. **"내가 독자라면 어디서 잠깐 멈추겠는가"** 하나만 떠올리면 된다.

### 자동광고 + 수동 1~2곳

| | 자동광고 | 수동배치 |
|---|---|---|
| 장점 | 새 글에도 자동으로 붙는다 | 정밀한 통제 |
| 단점 | 과밀 위험 | 손이 많이 간다 |

**자동광고로 전체를 깔되 핵심 자리 한두 곳만 수동.**
병용할 때는 자동광고 밀도를 한 단계 낮춘다 — 주연은 수동, 조연은 자동이다.

### 모바일을 먼저 본다

방문자 대다수가 휴대폰이다. 데스크톱만 보고 정하면 함정에 빠진다.

- 첫 화면(스크롤 전)을 광고가 점령하지 않았나
- 본문과 광고 사이 여백이 있나
- 앵커 광고의 **닫기(X) 버튼이 분명히 보이나**
- 전면 광고는 **페이지 전환 시에만**. 읽는 도중 덮으면 안 된다

### 절대 하지 않는 배치 넷

1. **콘텐츠 위장** — 광고를 본문 글씨·색과 똑같이
2. **클릭 강요 위치** — 메뉴·버튼 옆 (실수 클릭 유발)
3. **콘텐츠 없는 페이지의 광고** — 오류·빈 페이지
4. **화면 덮기** — 특히 닫기 버튼이 안 보이는 전면 광고

넷의 공통점은 **"방문자를 속이거나 가둔다"**는 것이다.
새 광고 형식이 나와도 그것만 물으면 판단된다.

### 밀도는 숫자로 검증한다

광고를 늘렸을 때 **RPM(1,000회 노출당 수익)이 같이 오르면 OK, 떨어지면 과밀 신호**다.
감이 아니라 숫자로 본다. 단 며칠이 아니라 **몇 주 단위 추세**로 본다.

## 5. 계정을 날리지 않는 수칙

`CONTRIBUTING.md` §10에 있다. 요지만 옮기면 —

**절대 하지 않는 것**: 내 광고 클릭, 지인에게 부탁, 트래픽 구매.
구글은 즉시 경고하지 않고 **데이터를 모은 뒤 한꺼번에 조치한다.**

**월 1회 정책 센터 확인.** 정지는 벼락이 아니다. 대개 그 전에 경고라는 노란불이 켜진다.
문제는 위반 자체가 아니라 노란불을 모르고 지나치는 것이다.

> 승인의 보상은 천천히 쌓이지만, **정지의 손실은 한순간에 전부다.**
> 계정은 보통 1인 1개이고, 이의 신청이 거부되면 새 계정 우회도 막힌다.

**정지 위험은 글이 늘수록 커진다.** 10편일 때는 다 볼 수 있지만 수백 편이면
어딘가 숨어 있을 확률이 오른다. 규모가 커질수록 검수 게이트와 월 1회 점검이 더 중요하다.

## 6. 우리 도구가 대신 막아 주는 것

책이 "사람이 조심하라"고 한 것 중 여럿을 시스템에 박아 뒀다.
**사람의 기억에 의존하는 규칙은 언젠가 깨지지만, 템플릿에 박아 둔 규칙은 깨지지 않는다.**

| 책이 경고한 것 | 우리가 막는 방법 |
|---|---|
| 검수 없이 발행 | `draft: true`가 기본. `publish_to_blog.py`가 `false`면 옮기기를 거부한다 |
| 면책 문구 누락 | 템플릿이 자동으로 붙인다. 개별 글로 못 끈다 |
| 단정적 투자 권유 | 니치 규칙 + `fact-auditor`가 BLOCKER로 잡는다 |
| 출처 없는 수치 | `writer`가 `research.md` 밖의 수치를 못 쓴다 |
| 같은 글 복제 | `fact-auditor`가 기존 글과 대조해 BLOCKER 판정 |
| 빈 카테고리 | 글 0편이면 목록·검색에서 자동으로 빠진다 |
| 광고 코드 흩어짐 | `extend_head.html` 한곳. GA 이중 삽입은 빌드가 실패한다 |
| 이미지 저작권 | 외부 이미지를 쓰지 않고 HTML+CSS로 직접 만든다 |
